# Content-Level Compression

This guide covers the content-level API: detecting what a payload is,
compressing it with the right strategy, and getting the original back.

## Quick start

```rust
use ogham::{compress_messages, CompressConfig, Message};

let result = compress_messages(
    vec![Message::new("tool", huge_tool_output)],
    CompressConfig::default(),
).await?;

for msg in &result.messages {
    println!("{}", msg.content);          // may contain <<ccr:HASH>> markers
}
println!("ratio: {:.2}", result.stats.ratio);
```

`CompressConfig::default()` enables reversible mode with an in-memory CCR
store. Set `ccr_store_path: Some(path)` to persist originals in SQLite
instead.

## Building a pipeline explicitly

For control over the store, metrics, observers, and cache alignment:

```rust
use std::sync::Arc;
use ogham::pipeline::DefaultCompressionPipeline;
use ogham::ccr::sqlite::SqliteCcrStore;

let store = Arc::new(SqliteCcrStore::open("ccr.db", 86_400)?);
let pipeline = DefaultCompressionPipeline::builder()
    .ccr_store(store.clone())
    .observer(my_audit_observer)      // anything implementing Observer
    .metrics(my_metrics_sink)         // anything implementing Metrics
    .align_cache()                    // stabilize bytes for KV-cache reuse
    .build();

let out = pipeline.run(&messages).await?;
```

Per-message failure is contained: if a compressor errors, that message passes
through unchanged and the error is reported via the `Observer`
(`CompressionEvent::Error`); the run still succeeds.

## Content-type detection

```rust
use ogham::detect;

let d = detect(text);
// d.content_type: JsonArray | SourceCode | SearchResults | BuildOutput
//                 | GitDiff | Html | PlainText
// d.confidence:   0.0..=1.0
```

Detection is regex/heuristic based and deterministic. `PlainText` is the
fallback; everything routes somewhere (see the routing table in
[architecture.md](architecture.md)).

## The compressors

| Name | Input | Reversible | What it does |
|---|---|---|---|
| `smart_crusher` | JSON arrays of objects | yes | keeps statistical outliers, samples representative items using knee-point detection over a bigram-uniqueness curve, replaces the rest with a CCR marker |
| `log_stripper` | build/CI logs | yes | detects the log format, scores line importance (errors highest), deduplicates repeated patterns, applies an adaptive cap |
| `ast_code` | source code, diffs | yes | strips comments, docstrings, and blank runs; preserves signatures, imports, and structure |
| `semantic` | prose, HTML, search results | yes | paragraph-level dedup; truncates long paragraphs preserving first/last sentences |
| `dedup_ref` | anything repetitive | yes | content-addressed dedup of repeated blocks across messages |
| `toon` | JSON / text | **no** | minification and whitespace collapse; lossy fast path |

Custom compressors implement `ogham_core::Compressor` and register via
`pipeline.register(...)` (or `add_compressor` through the
`CompressionPipeline` trait).

## CCR: getting originals back

Compressed output references originals by content hash:

```text
[tool:file_read] result cleared (512 tokens) — original retrievable via <<ccr:86a33abc...>>
```

```rust
use ogham::ccr::CcrStore;

if let Some(original) = store.retrieve("86a33abc...").await? {
    // full original text
}
```

Markers are generated by `ogham::ccr::marker_for(hash)`; keys by
`ogham::ccr::compute_key(bytes)` (MD5 hex — a content address, not a
security mechanism; do not change it, every stored marker depends on it).

A typical host exposes `retrieve` to the LLM as a tool so the model can pull
back full content on demand.

## Cache alignment

Provider and inference-server KV caches key on exact byte prefixes. Two
prompts differing only in whitespace waste cache slots.

```rust
use ogham::{align_text, align_messages};

align_messages(&mut messages);  // collapse whitespace runs, sort JSON keys
```

Enable it on the pipeline with `.align_cache()` to apply before compression.

## Conversation history (age-banded)

For multi-turn histories there is a simpler age-based helper, independent of
the agent rules:

```rust
use ogham::conversation::{compress_conversation_history, ConversationConfig};

// recent turns verbatim → middle turns via pipeline → old turns summarized
let stats = compress_conversation_history(
    &mut messages,
    &ConversationConfig::default(),   // preserve_recent: 4, compress_middle: 8
    &pipeline,
    &ctx,
).await?;
```

For structured (rather than first-sentence) summaries of the old band, use
`compress_conversation_history_with_summarizer` — see
[agent-context.md](agent-context.md#structured-summaries).

## Token counting

```rust
use ogham::counter_for_model;

let counter = counter_for_model("gpt-4o");        // exact with `tiktoken` feature
let counter = counter_for_model("claude-fable-5"); // calibrated estimate
let n = counter.count_messages(&messages);
counter.is_exact();                                // know which one you got
```

Claude tokenizers are not public, so Claude counts are always estimates;
`enforce_budget` compensates with a safety margin (default 5%) whenever the
counter reports `is_exact() == false`.
